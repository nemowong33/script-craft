# 架构设计（OpenClaw 版）

## 1. 核心设计理念

**网文改编漫剧 Agent** 采用**分层架构 + 双重质量门禁**的设计：

```
┌─────────────────────────────────────────────────────────┐
│ 知识层  webtoon-skill                                    │
│        ├─ adapt-method.md     （改编方法论）              │
│        ├─ output-style.md     （写作风格）                │
│        ├─ templates/           （文档结构模板）            │
│        └─ examples/            （参考示例）               │
├─────────────────────────────────────────────────────────┤
│ 流程层  .openclaw workspace 根文件                       │
│        ├─ IDENTITY.md          （身份）                   │
│        ├─ SOUL.md              （人格 / 边界）            │
│        ├─ USER.md              （用户画像）               │
│        ├─ TOOLS.md             （工具约定）               │
│        └─ AGENTS.md            （主流程 / 指令集 / 路由）  │
├─────────────────────────────────────────────────────────┤
│ 改编层  主 Agent（钳多多 / chandor）                         │
│        读取资源 → 拆解/创作 → 质量检查 → 落盘             │
├─────────────────────────────────────────────────────────┤
│ 校验层  Sub-Agents                                        │
│        ├─ breakdown-aligner    （8 维源头把关）            │
│        └─ webtoon-aligner      （11 维输出把关）           │
│          PASS/FAIL → 触发修改循环                         │
├─────────────────────────────────────────────────────────┤
│ 文档层  Workspace 业务数据                                │
│        ├─ novel/*.txt          （小说源文件）              │
│        ├─ plot-breakdown.md    （剧情拆解 + 分集标注）     │
│        └─ scripts/*.md         （单集剧本）                │
└─────────────────────────────────────────────────────────┘
```

## 2. 五层分层解析

### 2.1 知识层 — `webtoon-skill`
**定位**：可复用的"改编大脑"。
- 把方法论（adapt-method）、风格（output-style）、模板、示例封装成一个 **AgentSkills 兼容** 的技能包。
- 具备 YAML frontmatter（`name + description`），可被 OpenClaw 按 skill 发现机制加载。
- 在**任何改编阶段**（类型确定 / 剧情拆解 / 单集剧本 / 内容修订）都被主 Agent 调用。

**为什么要独立**：
- 改编知识与业务流程解耦，便于后续增加其他类型（如**短剧**、**有声剧**等）的平行 skill。
- 可被其他 workspace 以 `~/.openclaw/skills` 或项目 `skills/` 的方式共享。

### 2.2 流程层 — OpenClaw workspace 根文件
**定位**：OpenClaw 启动时会自动注入的 Agent 运行时上下文。
- `IDENTITY.md` → Agent 是谁。
- `SOUL.md` → Agent 怎么说话 / 边界在哪。
- `USER.md` → 用户是谁、偏好。
- `TOOLS.md` → 允许如何使用工具。
- `AGENTS.md` → **主流程 / 指令集 / 阶段路由**（最重量级的文件）。

### 2.3 改编层 — 主 Agent
**定位**：编排中枢。不直接"写作"，而是**调度 skill 产出 + 调度 aligner 校验 + 落盘**。
- 改编全部交给 `webtoon-skill`；
- 质量全部交给两个 aligner；
- 主 Agent 负责上下文读取、阶段路由、用户交互、循环控制。

### 2.4 校验层 — 两个 Sub-Agent（双重质量门禁）

| Sub-Agent | 作用域 | 维度 | 触发时机 |
|-----------|--------|------|---------|
| **breakdown-aligner** | 剧情拆解 | 8 维 | 每批次 6 章拆解完成后，**写盘前** |
| **webtoon-aligner**   | 单集剧本 | 11 维 | 每批次剧本创作完成后，**写盘前** |

**双重门禁的意义**：
- **源头把关**（breakdown-aligner）：确保后续剧本创作的"输入"是准确的。冲突误标 / 分集错误 / 类型特性缺失这类问题必须在拆解阶段解决，否则会被放大到每一集剧本里。
- **输出把关**（webtoon-aligner）：确保剧本"输出"与拆解一致、与方法论一致、跨集连贯、格式规范。

**失败循环**：
```
FAIL → webtoon-skill 按反馈修改 → 再次 aligner 检查 → 直到 PASS → 落盘
```

### 2.5 文档层 — Workspace 业务数据
**定位**：成品的单一真相源。
- `plot-breakdown.md` 是**生命周期中贯穿所有阶段的文档**：类型确定时创建 → 拆解阶段追加剧情点 → 剧本创作阶段更新"使用状态"。
- `scripts/Episode-XX.md` 是每一集的独立文档，便于分发、增量修改、版本管理。

## 3. 关键设计决策

### 3.1 为什么改编与校验分离？
如果把"改编 + 自检"放在同一个 Agent 里，实践中会出现：
- 模型倾向于**自我肯定**，对自己产出内容的问题发现能力弱。
- 一次长 prompt 难以兼顾"创作"和"严苛检查"两种矛盾心态。

独立 Sub-Agent 的好处：
- 独立上下文，独立"严苛人设"（见 `agents/*/SOUL.md`）。
- 产出 PASS/FAIL 的结构化结果，主 Agent 可自动化循环。

### 3.2 为什么用 6 章为一个拆解批次？
- `adapt-method.md` 中"冲突密度"的统计口径就是 6 章。
- 6 章约 12000-24000 字，既足够识别 1 个核心冲突 + 若干钩子，又不会让主 Agent 上下文过长。

### 3.3 为什么剧情点带状态（未用 / 已用）？
- 拆解与剧本创作是**异步**的：用户可能先连着跑多次 `/拆解`，再开始 `/出稿`。
- "状态"字段让主 Agent 在 `/出稿` 时能自动识别"连续的未用剧情"并批量创作，同时避免重复使用。

### 3.4 为什么第 20 集特别重要？
- 它是**免费段的最后一集**，承担付费转化责任。
- `webtoon-aligner` 的第五步明确把"第 20 集"列为**特殊集数重点检查**项。

## 4. 和 OpenClaw 规范的对齐点

| OpenClaw 规范 | 本项目实现 |
|---------------|-----------|
| Workspace 唯一工作目录 | 项目根即 workspace，所有业务数据 + `.openclaw/` 配置同处 |
| Bootstrap 文件注入 | 采用 IDENTITY/SOUL/USER/TOOLS/AGENTS 五件套 |
| Skills（AgentSkills 兼容） | `webtoon-skill/SKILL.md` 带 YAML frontmatter |
| Sub-Agent 独立子目录 | `agents/<name>/{IDENTITY,SOUL,AGENTS}.md` + frontmatter |
| Workspace 优先级 | 所有 skill 和 agent 配置放 `<workspace>/.openclaw/`，不污染全局 `~/.openclaw/` |
| 中文响应规则 | 在 `SOUL.md` 和 `AGENTS.md` 总体规则中显式要求 |
